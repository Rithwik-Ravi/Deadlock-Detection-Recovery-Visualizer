    Deadlock detection and recovery

    This page collects the theory behind the tool. The figure, numbers, and trace on the Detection tab follow the algorithm below step by step.

    Conditions for deadlock

    A deadlock can arise only when all four Coffman conditions hold at once:

    1. Mutual exclusion: resources cannot be shared.
    2. Hold and wait: a process holds resources while waiting for others.
    3. No preemption: resources cannot be taken away by force.
    4. Circular wait: a closed chain P0 → P1 → … → P0 exists.

    Resource allocation graphs

    Processes are circles and resource types are boxes, with one small dot per instance. A solid blue edge from a box to a process is an allocation. A dashed red edge from a process to a box is a request.

    With multiple instances per resource type, a cycle is necessary for deadlock but not sufficient. Deadlock exists only if no process in the cycle can ever get the units it lacks.

    Detection algorithm

    The Silberschatz multi-instance algorithm assumes that any process whose request can be met will finish and release everything it holds.

    Work   = Available
Finish[i] = (Allocation[i] == 0)        for each i

repeat:
  find the lowest i with Finish[i] == false
                    and Request[i] <= Work
  if none: stop
  Work      = Work + Allocation[i]
  Finish[i] = true
  rescan from i = 0

deadlocked = { i : Finish[i] == false }

    The algorithm runs in O(m × n²) time for n processes and m resource types. It rescans from index 0 after every finish, because the freed units may now satisfy a process that was skipped earlier.

    Recovery strategies

    Abort all terminates every deadlocked process and loses all their work. Abort one by one terminates victims one at a time and runs detection again after each. Preempt and roll back takes resources from a victim and loses the work since its checkpoint.

    Debt-Ledger Recovery

    Debt-Ledger Recovery suspends lender processes in place and lends their units. Lenders lose no progress: they resume once the debt is repaid. A lend plan L is approved only if detection on the ledger-augmented state finds no deadlock:

    Allocation' = Allocation - L
Request'    = Request + L
Available'  = Available + sum(L)

    The safe sequence from that run becomes the repayment order. At every step the conservation invariant holds:

    Available + sum(Allocation) + in_transit == Total
